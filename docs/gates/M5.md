# Gate report: M5 — Force-field description and total evaluation

Written by Claude on 2026-11-17, at the author's request. The design is in
`docs/design/M5-architecture.md`. Suite on branch `claude/m4-m5`: 226 passed, 0 failed.

## Evidence per requirement

- **R5.1** (data model, canonical order):
  - `system::System` and its parts follow spec/system-package.md §3–§5.
  - `validate` rejects out-of-range parameters and repeated or out-of-range indices:
    `invalid_systems_are_errors`, 16 cases.
  - `topology` expands in canonical order: `canonical_order_of_atoms_and_interactions`, with three
    components that include the same molecule type twice.
- **R5.2** (total evaluation, named terms):
  - `forcefield::ForceField::evaluate` returns the energy, forces, virial and named terms. The
    terms add up exactly, because the energy is their sum.
  - Every term of water-2 and of the test molecule matches an independent Python evaluation to
    1e-10 relative, also periodic: `water2_terms_match_independent_evaluation`,
    `test_molecule_terms_match_independent_evaluation`.
- **R5.3** (conformance tests of spec/force-provider.md §6):
  - Items 1–6 (FD forces with a step scan, FD virial, terms sum, momentum, finiteness and
    shape, bitwise determinism) pass on water-2 and on the test molecule.
  - Each system is checked both non-periodic and periodic with Ewald in a triclinic cell:
    `conformance_*`, four tests.
- **R5.4** (water-2): the fixture's parameters and positions are in the test, cited. An
  independent script read the fixture files directly, so a transcription error would have shown
  up as a mismatch.

## Deviations and open issues

- **No package reader:** there is no reader for `system.json`/`positions.npy`. Reading packages
  belongs to the engine (ucmd-io), and the crate has no dependencies.
- **Per-call setup:** the non-bonded modules of M3 rebuild their exclusion map on every call
  (O(N²) memory). That is acceptable for the test systems, not for large ones.
